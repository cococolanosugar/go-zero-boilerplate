# Proposal: 通用对象存储与文件上传服务 (pkg/storage & sys_file)

## 1. 业务背景与问题阐述 (Why)

在企业内部中台与业务开发中，文件与对象存储（头像上传、业务单据附件、合同图片、Excel 导入文件等）是几乎所有业务域都不可或缺的核心基建。
目前 `go-zero-boilerplate` 的现状如下：
1. **缺少文件上传中台能力**：网关层尚未支持 `multipart/form-data` 文件上传接口，前端头像（Avatar）等字段只能填入外部 HTTP URL，无法本地上传真实图片与文件。
2. **缺少可插拔存储驱动抽象**：缺少类似 RuoYi OSS 的抽象层（本地磁盘、MinIO、阿里云 OSS、AWS S3），导致业务如果需要存储文件，必须手写特定 SDK，造成厂商锁死与代码混乱。
3. **缺少文件安全与审计记录**：上传的文件缺少哈希秒传校验、文件大小限制与危险后缀（`.exe`、`.sh` 等）防护，也缺少 `sys_file` 审计追溯台账。

因此，作为第二阶段（P0-2），构建轻量、可插拔且具备生产安全性的通用文件上传与对象存储服务迫在眉睫。

## 2. 方案与核心价值 (What)

1. **通用驱动抽象 (`pkg/storage`)**:
   - 定义统一的 `Driver` 接口：`Upload`、`UploadBytes`、`Delete`、`GetUrl`。
   - 实现开箱即用的 `LocalStorageDriver`（零外部依赖，本地磁盘持久化 + 网关静态文件代理），并预留 MinIO / OSS 扩展插槽。
   - 内置安全策略：SHA-256 自动计算去重、可执行文件黑名单防护、最大文件尺寸限制。
2. **文件台账数据库迁移 (Atlas `sys_file`)**:
   - 创建 `sys_file` 数据表，记录原始文件名、存储路径、扩展名、MIME 类型、文件字节大小、SHA-256 哈希值、上传人与时间。
3. **网关 RESTful 上传接口与静态挂载**:
   - 在 `app/gateway/desc/system.api` 暴露 `POST /api/v1/system/file/upload` 接口。
   - 在网关启动入口挂载 `/uploads/` 静态文件服务，使上传的文件可直接由前端浏览器访问回显。
4. **前端 SDK 与头像/附件联动**:
   - 自动生成前端 `@zero/api` 的 `uploadFile` 调用方法。
   - 在员工管理或通用表单中验证文件真实上传回显。
