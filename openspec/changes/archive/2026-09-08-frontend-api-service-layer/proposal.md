## Why

Currently, all frontend API endpoints generated by `goctl api ts` in `@zero/api` reside in a single flat file (`gateway.ts`), lacking business domain partitioning. Furthermore, page components throughout the application manually duplicate try-catch blocks to display `message.error()` and manually transform go-zero `{ list, total }` responses to Ant Design ProTable's `{ data, total, success }` contract.

Referencing the industry-standard Ant Design Pro architecture, this change introduces domain-partitioned service directories (`services/auth`, `services/system`, `services/order`, etc.), a unified error interception and notification mechanism (`requestErrorConfig`), and a zero-boilerplate ProTable request adapter.

## What Changes

- **Domain-Partitioned Services**: Reorganize API requests into dedicated service namespaces under `frontend/packages/api/src/services/` (e.g., `auth`, `user`, `order`, `system/{users,roles,menus,apis,dicts,logs}`) while preserving root barrel export backward compatibility.
- **Request & Response Interceptors**: Enhance `@zero/api` client engine (`gocliRequest.ts`) to support interceptor chains, request metadata injection (trace ID, locale), and a configurable `errorHandler`.
- **Ant Design Pro `requestErrorConfig`**: Introduce application-level unified error handling configuration in `apps/admin/src/requestErrorConfig.ts` and `apps/portal/src/requestErrorConfig.ts`, integrating with Ant Design `App.useApp()` (`message`, `notification`) to automatically surface errors according to severity (`showType`), eliminating repetitive manual `try...catch` blocks across pages.
- **ProTable Request Adapter**: Provide a lightweight, type-safe `toProTableRequest` helper function in `@zero/api` that automatically maps go-zero pagination parameters and response payloads to ProTable requirements.
- **Application Services Facade & Page Refactoring**: Provide `src/services` structure in `admin` and refactor representative CRUD pages (such as User Management, Role Management, Orders) to demonstrate clean, declarative, and robust business code.

## Capabilities

### New Capabilities

- `frontend-service-layer`: Covers domain-partitioned API services, unified HTTP/business error interception with Ant Design feedback integration, and automated ProTable pagination adapter.

### Modified Capabilities

None.

## Impact

- `frontend/packages/api`: New `services/` directory, new `adapter.ts`, updated `gocliRequest.ts` and `index.ts`. All existing flat exports remain preserved for 100% backward compatibility.
- `frontend/apps/admin`: New `requestErrorConfig.ts`, updated `app.tsx`, new `src/services/` facade, refactored CRUD pages.
- `frontend/apps/portal`: New `requestErrorConfig.ts`, updated `app.tsx`, integrated domain services.
- Dependencies: No new third-party dependencies required; built entirely on existing React 18, Ant Design 6.x, and ProComponents.
