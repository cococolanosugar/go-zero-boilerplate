## Purpose

为开发者与架构师提供全栈微服务体系的三层调用依赖拓扑可视化、微服务元数据资产卡片、实时健康探针监控以及契约调试直达能力。

## ADDED Requirements

### Requirement: 微服务三层架构依赖拓扑图谱
系统 SHALL 在服务治理页面 `/services` 渲染清晰的三层架构拓扑图谱（客户端接入层 ➔ 统一网关 BFF ➔ gRPC 核心微服务 ➔ 基础设施持久层），并动态标示各链路通信协议（HTTP RESTful, gRPC Protobuf, MySQL TCP, Redis RESP, Temporal gRPC）。

#### Scenario: 浏览微服务架构拓扑
- **WHEN** 用户访问技术门户 `/services` 页面
- **THEN** 系统展示三层分层拓扑图，每个服务节点清晰呈现名称、代号、端口号以及当前运行状态微标

#### Scenario: 节点点击与上下游链路高亮
- **WHEN** 用户点击拓扑图中的任一微服务节点（例如 Titan 交付微服务）
- **THEN** 系统高亮显示与其直连的上游网关调用链路与下游基础设施依赖链路，并在侧边弹出抽屉展示其完整资产详情

### Requirement: 微服务资产元数据与契约联动
系统 SHALL 提供各微服务的标准化元数据资产卡片，展示技术负责人/团队、开发框架、端口协议、业务责任边界以及 Proto 契约源文件定位，并提供直达沙箱调试入口。

#### Scenario: 从服务卡片直达 API Hub 调试
- **WHEN** 用户在微服务资产卡片或抽屉中点击「在 API Hub 中调试该服务」
- **THEN** 系统自动路由进入 `/api-hub` 并联动高亮该微服务的接口契约列表

### Requirement: 实时服务探针与注册中心租约监控
系统 SHALL 提供统一网关及各微服务的实时连通性探针监测与 Nacos / Etcd 实例注册状态，支持一键刷新健康检查。

#### Scenario: 实时探测与刷新微服务健康状态
- **WHEN** 用户进入服务目录页面或点击「刷新探针」按钮
- **THEN** 系统即时发起网络连通性探测，并在拓扑图和卡片上更新各服务的健康徽标与响应延迟
